# 🔐 Система контроля доступа

В боте реализована гибкая система контроля доступа с тремя режимами работы.

## 📋 Режимы работы

### 1. **Open (Открытый доступ)**
```env
ACCESS_MODE=open
```
- ✅ Доступ для всех пользователей
- Регистрация автоматическая
- Подходит для публичного бота

### 2. **Whitelist (Белый список)**
```env
ACCESS_MODE=whitelist
ADMIN_TELEGRAM_IDS=123456789,987654321
```
- ✅ Доступ только для одобренных пользователей
- Новые пользователи видят сообщение "Ожидайте одобрения"
- Администраторы одобряют через веб-админку
- Админы (из ADMIN_TELEGRAM_IDS) получают доступ автоматически

### 3. **Invite Only (Только по приглашениям)**
```env
ACCESS_MODE=invite_only
INVITE_TOKEN=your_secret_token_123
ADMIN_TELEGRAM_IDS=123456789
```
- ✅ Доступ только по токену приглашения
- Пользователь должен ввести: `/start your_secret_token_123`
- Самый строгий режим
- Подходит для закрытых ботов

## ⚙️ Настройка в .env

```env
# Режим доступа: open, whitelist, invite_only
ACCESS_MODE=whitelist

# Telegram ID администраторов (через запятую)
# Как узнать свой ID: @userinfobot
ADMIN_TELEGRAM_IDS=123456789,987654321

# Токен приглашения (для режима invite_only)
INVITE_TOKEN=secret_invite_code_2024
```

## 👥 Управление пользователями

### Через веб-админку (http://localhost:8000/admin)

1. Откройте раздел **"Пользователи"**
2. Найдите нужного пользователя
3. Отметьте галочки:
   - **is_approved** - разрешить доступ
   - **is_blocked** - заблокировать пользователь
   - **is_admin** - сделать администратором

### Роли пользователей:

| Роль | Описание | Права |
|------|----------|-------|
| **Обычный пользователь** | is_approved=True | Доступ к боту |
| **Администратор** | is_admin=True | Полный доступ + в списке ADMIN_TELEGRAM_IDS |
| **Заблокированный** | is_blocked=True | Доступ запрещён |
| **Неодобренный** | is_approved=False | Ожидает одобрения |

## 🎯 Примеры использования

### Пример 1: Открытый бот для всех
```env
ACCESS_MODE=open
```
Любой пользователь может начать пользоваться ботом.

### Пример 2: Бот для компании (Whitelist)
```env
ACCESS_MODE=whitelist
ADMIN_TELEGRAM_IDS=123456789
```

1. Сотрудник запускает бота `/start`
2. Видит: "Ожидайте одобрения"
3. Администратор заходит в админку
4. Находит пользователя по telegram_id или username
5. Ставит галочку **is_approved**
6. Сотрудник получает доступ

### Пример 3: Закрытый бот с токеном
```env
ACCESS_MODE=invite_only
INVITE_TOKEN=mycompany2024
ADMIN_TELEGRAM_IDS=123456789
```

1. Вы даёте токен пользователю: `mycompany2024`
2. Пользователь вводит: `/start mycompany2024`
3. Бот проверяет токен и даёт доступ
4. Можно сменить токен в любой момент

## 🔒 Дополнительные возможности

### Блокировка пользователя
В админке установите `is_blocked = True` для пользователя.
Он получит сообщение: "Ваш доступ к боту заблокирован"

### Назначение администратора

**Вариант 1 - через .env (рекомендуется):**
```env
ADMIN_TELEGRAM_IDS=123456789,987654321
```

**Вариант 2 - через админку:**
Установите галочку `is_admin = True` для пользователя.

### Просмотр статистики

В разделе "Пользователи" админки вы можете видеть:
- Кто использует бота (last_activity)
- Кто ждёт одобрения (is_approved=False)
- Кто заблокирован (is_blocked=True)
- Какой токен использовал пользователь (invite_token)

## 🛡️ Безопасность

### ✅ Рекомендации:

1. **Используйте сложные токены:**
   ```python
   import secrets
   print(secrets.token_urlsafe(16))
   # Результат: "xZ7yQ3kM9pL2vN4r"
   ```

2. **Меняйте токены периодически:**
   - Обновите `INVITE_TOKEN` в `.env`
   - Перезапустите бота

3. **Не публикуйте токены:**
   - Не коммитьте `.env` в git
   - Отправляйте токены приватно

4. **Регулярно проверяйте список пользователей:**
   - Блокируйте подозрительных
   - Удаляйте неактивных

### ❌ Что НЕ делать:

- Не используйте простые токены типа "123" или "password"
- Не давайте токен публично
- Не оставляйте режим "open" для внутреннего бота

## 📊 Мониторинг доступа

### SQL-запросы для статистики:

```sql
-- Пользователи ожидающие одобрения
SELECT telegram_id, username, first_name, created_at 
FROM users 
WHERE is_approved = false AND is_blocked = false
ORDER BY created_at DESC;

-- Заблокированные пользователи
SELECT telegram_id, username, first_name 
FROM users 
WHERE is_blocked = true;

-- Статистика регистраций по дням
SELECT DATE(created_at) as date, COUNT(*) as count
FROM users
GROUP BY DATE(created_at)
ORDER BY date DESC;
```

## 🔄 Миграция режимов

### Переход с open на whitelist:

1. Измените `.env`:
   ```env
   ACCESS_MODE=whitelist
   ```
2. Перезапустите бота
3. Существующие пользователи сохранят доступ (is_approved=true)
4. Новые будут требовать одобрения

### Переход на invite_only:

1. Сгенерируйте токен
2. Обновите `.env`:
   ```env
   ACCESS_MODE=invite_only
   INVITE_TOKEN=новый_токен
   ```
3. Перезапустите бота
4. Сообщите токен новым пользователям

## 📝 FAQ

**Q: Как узнать свой Telegram ID?**  
A: Напишите боту @userinfobot или @getmyid_bot

**Q: Можно ли использовать несколько токенов?**  
A: В текущей версии - один токен. Но можно вручную одобрять через админку.

**Q: Что делать если токен утёк?**  
A: Смените `INVITE_TOKEN` в `.env` и перезапустите бота.

**Q: Администраторы видят всех пользователей?**  
A: Да, в веб-админке доступна вся информация о пользователях.

**Q: Можно ли ограничить доступ по IP?**  
A: Telegram не предоставляет IP пользователей ботам, поэтому нет.
